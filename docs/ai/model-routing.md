# 模型選擇與升級

依「不確定性 × 影響範圍 × 失敗成本」選能力，不因檔案多就用最強模型。
明確的文件、設定轉接與局部測試用目前工具；授權、憑證、檔案讀寫邊界、跨服務契約及重大架構需要高能力推理與獨立 reviewer 或使用者。
兩次有意義的修正仍失敗就重查根因，不改 mock／any／測試預期換綠燈。若需要升級而不可用，記錄具體風險與待審項目。
實際模型名稱以本次環境證據為準；本 repo 不維護價格、供應商排名或固定版本表。委派、切模型與持續自動執行都依使用者當次授權。
