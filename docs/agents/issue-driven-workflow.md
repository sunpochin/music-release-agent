# Issue 與交接

獨立成果、需延期、外部依賴、跨工作日／模型的任務先搜尋既有 Issue，再建立或沿用；不要重複建票。
同一個聊天中可完成的明確任務可直接用 PR 記錄。新發現的獨立工作先記錄，不靜默擴張目前範圍。

最小交接內容：Why、Scope／不包含什麼、相關檔案、驗收條件、測試、資料／隱私／發布風險（沒有也寫無）、阻礙與下一步。
續作時記錄目前 branch／worktree、base／head SHA、實際 Issue／PR URL、已完成與未完成項目；repo 與程式碼是實作真相，Issue 連過去即可。
標題使用清楚的 `type: 描述`。可在內文記錄實際模型與環境，不從裝置或工具品牌猜模型，也不複製來源專案會過期的三家模型版本前綴。
